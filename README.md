# منصة السلامة — إدارة الأمن والسلامة والصحة المهنية HSE

منصة ويب مؤسسية موحدة باللغة العربية (RTL) لمتابعة وتحليل وإدارة الأمن والسلامة والصحة المهنية في مشاريع البنية التحتية: الجولات والتفتيش الميداني، رصد المخاطر والمخالفات والحوادث، الإجراءات التصحيحية، التحليل والتقارير ودعم اتخاذ القرار.

## المزايا الرئيسية

- **لوحة تحكم تنفيذية** بمؤشرات ورسوم بيانية حية من قاعدة البيانات، مع فلاتر (الفترة، المشروع، النوع، المقاول، الراصد، الخطورة، التصنيف، الحالة).
- **إدارة المشاريع** والمقاولين والاستشاريين وتوزيع الراصدين.
- **الجولات الميدانية** مع تحقق جغرافي GPS من الحضور (Geofencing) وتسجيل الاستثناءات.
- **25 نموذج تفتيش ذكي** (PPE، مرتفعات، حفريات، رافعات، كهرباء، أماكن مغلقة، أعمال ساخنة… إلخ) قابلة للتخصيص، بنتائج: مطابق / غير مطابق / غير منطبق / يحتاج متابعة.
- **الملاحظات والمخالفات** بسير عمل كامل: مسودة ← مسجلة ← تحت المراجعة ← معتمدة ← محالة ← جارٍ التنفيذ ← بانتظار التحقق ← مغلقة (+ مرفوضة / معاد فتحها / متأخرة / مصعدة / حرجة بإيقاف عمل).
- **تقييم المخاطر** بمصفوفة 5×5 (الاحتمالية × الأثر) ومخاطر متبقية.
- **الحوادث والإصابات** مع تحليل الأسباب الجذرية (5 Whys / Fishbone / RCA) وشبه الحادثة Near Miss.
- **الإجراءات التصحيحية CAPA** بأدلة تنفيذ وتحقق وتصعيد تلقائي عند التأخير.
- **سجل «الإجراءات المتخذة»** على الملاحظات والإجراءات التصحيحية والحوادث والتصاريح: أي مستخدم له صلاحية على المشروع يوثق ما نُفذ (نص + مرفقات + نسبة إنجاز اختيارية تحدّث الإجراء تلقائياً) في سجل زمني باسم صاحبه، ولا يُقبل طلب التحقق أو الإغلاق قبل توثيق إجراء واحد على الأقل.
- **تصاريح العمل** (ساخنة، حفر، ارتفاع، رفع، كهرباء، أماكن مغلقة، إغلاق طرق).
- **مؤشرات أداء** ببطاقة تعريف لكل مؤشر (المعادلة، المصدر، الدورية، المستهدف): TRIR، LTIFR، نسب التنفيذ والالتزام والإغلاق…
- **تقييم المقاولين والاستشاريين** ببطاقات أداء شهرية وترتيب.
- **خريطة GIS تفاعلية** (Leaflet + OpenStreetMap) بمواقع المشاريع والملاحظات والحوادث والمناطق الساخنة.
- **مركز إشعارات وتصعيد تلقائي** كل 15 دقيقة للملاحظات والإجراءات المتأخرة والجولات الفائتة، مع **صفحة «التصعيد والمهل»** لمدير النظام: تعديل مدد المعالجة (SLA) لكل درجة خطورة، ومهل التصعيد بعد الاستحقاق، والتنبيه قبل الاستحقاق، وقوائم حية بكل السجلات المصعدة.
- **حذف آمن**: حذف نهائي للمشاريع/المستخدمين/المقاولين الخالين من السجلات فقط، مع اقتراح الأرشفة أو التعطيل تلقائياً عند وجود ارتباطات (حفاظاً على سجل التدقيق).
- **فلاتر ذكية** تُطبق فور الاختيار دون الحاجة لزر تطبيق.
- **زر تعديل في جميع الجداول** حسب صلاحية المستخدم، مع تغيير الحالة من داخل نافذة التعديل وفق الانتقالات المتاحة في سير العمل.
- **حالات مخصصة (وسوم)** يعرّفها مدير النظام من الإعدادات (مثل: بانتظار المقاول، بانتظار توريد مواد) وتُسند للملاحظات والإجراءات والحوادث والتصاريح والمخاطر كشارة إضافية بجانب الحالة الأساسية، وتظهر في الجداول ويمكن التصفية بها — دون التأثير على التصعيد والمؤشرات.
- **تقارير قابلة للطباعة** (PDF عبر المتصفح بنفس الهوية البصرية) وتصدير CSV/Excel بترويسات عربية واستيراد.
- **عمل دون اتصال Offline** للراصد الميداني: Service Worker + قائمة انتظار محلية تُزامن تلقائياً عند عودة الاتصال.
- **تحليل ذكي**: تصنيف آلي من الوصف، اقتراح الخطورة، اكتشاف التكرار، التنبؤ بالمشاريع الأعلى خطورة، ملخص تنفيذي آلي.
- **أفضل الممارسات السعودية**: تاريخ هجري مزدوج (أم القرى) في الترويسات والتقارير؛ مراقبة موسمية لحظر العمل تحت أشعة الشمس (15 يونيو–15 سبتمبر، 12:00–15:00) بتنبيه تلقائي في اللوحة والواجهة الميدانية؛ بيانات المصاب ومهلة إبلاغ التأمينات الاجتماعية GOSI (3 أيام) بتنبيه آلي ومؤشر التزام؛ مكتبة مراجع نظامية سعودية (نظام العمل، SBC، الدفاع المدني…) قابلة للإدارة من الإعدادات؛ وسجل اجتماعات التوعية Toolbox Talks بمؤشر تغطية يومية.
- **أمان**: تشفير كلمات المرور (scrypt)، جلسات HttpOnly، صلاحيات RBAC، تحقق من المدخلات، سجل تدقيق شامل، أرشفة بدل الحذف، نسخ احتياطي.
- **وضعان نهاري وليلي** وتصميم متجاوب (حاسب / لوحي / هاتف).

## المتطلبات

- **Node.js 22.5 أو أحدث** فقط (قاعدة البيانات SQLite مدمجة عبر `node:sqlite` — لا حاجة لأي تثبيت إضافي).

## التشغيل المحلي

```bash
cd safety
npm install          # مرة واحدة (express + multer)
npm run seed         # تهيئة قاعدة البيانات والبيانات التجريبية
npm start            # http://localhost:3000
```

> ملاحظة: `npm run seed` يعيد تهيئة البيانات بالكامل (يمسح الموجود). المنفذ قابل للتغيير عبر `PORT=8090 npm start`.

## قاعدة البيانات

- **SQLite** افتراضياً (ملف `data/hse.db`) — مثالية للتجربة والتشغيل المحلي، ويمكن تغيير المسار عبر `HSE_DB`.
- المخطط مكتوب بـ SQL قياسي؛ للنقل إلى **PostgreSQL/MySQL** استبدل `INTEGER PRIMARY KEY AUTOINCREMENT` بـ `SERIAL`/`AUTO_INCREMENT` ودوال التاريخ (`datetime('now')` → `NOW()`)، وطبقة الوصول محصورة في `server/db.js`.
- **نسخ احتياطي**: من واجهة مدير النظام (سجل العمليات ← نسخة احتياطية) أو بنسخ ملف `data/hse.db`. **الاستعادة**: إيقاف الخادم واستبدال الملف.

## خيارا الاستضافة الموصى بهما

| الخيار | التكلفة | سهولة الإدارة | الملاءمة |
|---|---|---|---|
| **VPS سعودي/إقليمي** (مثل خوادم STC Cloud أو أي VPS بنظام Ubuntu) | ~20–40$ شهرياً | متوسطة (تحكم كامل) | **الأنسب** — بيانات حكومية تبقى داخل المملكة، وSQLite يحتاج قرصاً دائماً |
| **Railway / Render** (حاويات بقرص دائم) | 5–20$ شهرياً | عالية (نشر بنقرة من GitHub) | مناسب للتجربة والإطلاق السريع؛ راجع سياسة موقع البيانات قبل الاعتماد |

> منصات الواجهات الثابتة (Vercel/Netlify) لا تناسب هذا المشروع لأنه يتضمن خادماً وقاعدة بيانات ملفية.
> المستودع: <https://github.com/omarslamat1000-maker/hse-app>
> ملف خط النشر جاهز في `deploy/github-ci.yml` — لتفعيله انسخه إلى `.github/workflows/ci.yml` من واجهة GitHub
> (Add file ← Create new file) أو بعد توسيع صلاحية الرمز: `gh auth login -s workflow` ثم أعد الملف وادفعه.
> عند التفعيل تعمل الاختبارات (87 + 18) تلقائياً قبل كل نشر.

## النشر على خادم (إنتاج)

1. انسخ المجلد إلى الخادم وثبّت Node.js 22+.
2. `npm install --omit=dev && npm run seed` (أول مرة فقط).
3. شغّل عبر مدير عمليات مع إعادة تشغيل تلقائي:
   ```bash
   npx pm2 start server/index.js --name hse -- PORT=3000
   # أو خدمة systemd / NSSM على Windows
   ```
4. ضع المنصة خلف Reverse Proxy (Nginx/IIS) مع **HTTPS** — إلزامي لعمل تحديد الموقع GPS والكاميرا من الهاتف.
5. جدولة نسخ احتياطي دوري لملف `data/hse.db` ومجلد `server/uploads`.
6. غيّر كلمات مرور الحسابات التجريبية فور النشر.

## الربط المستقبلي

- **الإشعارات الخارجية**: البنية جاهزة — أضف قناة (بريد/SMS/WhatsApp Business) داخل `escalation.js` (`notifyAdmins`/`notifyUser`) دون تغيير بقية النظام.
- **الذكاء الاصطناعي**: نقاط `/api/ai/*` تعمل حالياً بقواعد استدلالية، ويمكن استبدالها بنماذج لغوية أو تحليل صور (رصد عدم ارتداء PPE) مع بقاء القرار النهائي للمختص.
